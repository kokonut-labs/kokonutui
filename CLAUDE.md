# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**KokonutUI** is an open-source UI component library website (kokonutui.com). It showcases 100+ UI components built with Next.js, React, and Tailwind CSS. The site is a documentation/showcase platform: users install components into their own projects via the shadcn CLI (`npx shadcn@latest add @kokonutui/<name>`).

## Commands

```bash
bun run dev            # Dev server with Turbopack
bun run build          # Production build

bun run check:changed  # Biome, typecheck and knip on what this branch changed. Run before every push.
bun run lint           # Biome on the whole repo (CI runs `biome ci`)
bun run knip           # Unused files and packages (CI runs it too)
bun x ultracite fix    # Format and auto-fix lint issues

bun run ./scripts/build-registry.ts  # Rebuild public/r/*.json, registry.json and public/llms.txt
```

`bun x ultracite fix` fails on paths with parentheses like `app/(root)`. Use `bunx biome check --write "./app/(root)/..."` there.

## Architecture

### App Router Route Groups

- `app/(root)/`: marketing/landing pages with `Header` + `Footer` layout.
- `app/docs/`: Fumadocs documentation. Catch-all `[[...slug]]` renders MDX files from `content/docs/`.
- `app/api/search/`: Orama full-text search API used by Fumadocs.

### Key Directories

- `components/kokonutui/`: the 100+ components that ship in the registry, one file each.
- `components/ui/`: shadcn/ui primitives (button, textarea, dropdown-menu, drawer, card). Some components depend on them through `registryDependencies`.
- `components/landing/`: homepage sections (`home/` holds the current homepage).
- `components/mdx/`: MDX renderers: `Preview`, `PreviewClient`, `PreviewTemplate`, code display, package-manager tabs.
- `content/docs/<category>/`: one MDX page per component, grouped by category (ai, buttons, cards, inputs, media, navigation, texts, backgrounds).
- `registry/`: registry entries (components, hooks, lib), combined in `registry/index.ts`.
- `hooks/`: the 4 hooks that ship in the registry (auto-resize-textarea, click-outside, copy-to-clipboard, mobile).
- `lib/`: `utils.ts` (cn helper, ships in the registry), `action.ts` (server actions), `source.ts` (Fumadocs loader), `demo.tsx` (lazy docs demos, injected by `lib/mdx/remark-lazy-demos.ts`).
- `public/r/` and `registry.json`: generated by `scripts/build-registry.ts`. CI rebuilds and commits them on `main`; don't edit by hand.

### Component Source Serving

`lib/action.ts` contains Server Actions that read `.tsx` source files from `components/kokonutui/` at runtime (using React `cache()`). This powers the copy-to-clipboard feature in documentation previews.

### Registry System

Each component has an entry in `registry/registry-components.ts` (name, dependencies, registryDependencies, files). Dependencies are written by hand, so every npm import in a component must be listed there. The build script embeds the source files into `public/r/{name}.json`.

## Tech Stack

- **Next.js 16** (App Router) + **React 19**
- **TypeScript** (strict mode), path alias `@/*` → `./*`
- **Tailwind CSS v4**
- **Motion** (Framer Motion v12) for animations
- **Fumadocs** for documentation
- **Biome** via Ultracite (`biome.jsonc`) and **knip** (`knip.json`)
- **Bun** as package manager

## Important Patterns

- Use the `@/` path alias, never relative imports across directories. The shadcn CLI only rewrites `@/` imports.
- When adding a component, add its entry to `registry/registry-components.ts`, its docs page in `content/docs/<category>/`, and run the build-registry script.
- Demo data inside components is intentional: a component should look complete right after `shadcn add`.
- The site uses Vercel Analytics and Speed Insights; there is no custom tracking.

## Traps

- Tailwind v4 `scale-*`, `translate-*` and `rotate-*` set the CSS `scale`/`translate`/`rotate` properties, not `transform`. `transition-[transform]` won't animate them; use `transition-transform` or list `scale`/`translate`.
- `useReducedMotion()` is null on the server. Anything it changes in the first render causes a hydration mismatch for reduced-motion visitors, so only change transitions or apply the reduced version after mount.
- The docs site's CSS hides bugs consumers hit. Its theme tokens (`--card`, `--muted`, ...) are incomplete and `next/image` allows any remote host, so a component that looks right here can break in a fresh shadcn app.

## Never

- Never make a registry component need app-level setup: no `next-themes`, no `next/font`. `next/image`, `next/link` and `usePathname` are fine.
- Never rely on site-only CSS, keyframes or assets (`/logo.svg`, `globals.css` classes) in a registry component.
- Never edit `public/r/*.json` or `registry.json` by hand.
- Never add a file or package that nothing uses; knip fails CI.
